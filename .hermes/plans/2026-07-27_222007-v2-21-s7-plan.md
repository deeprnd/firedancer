> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Close V2.21.S7 by making the retail runtime trust surface explicit and complete across docs, CLI surface naming, evidence packaging, and closure artifacts.

## 1. Story Contract vs Current Repo State

### What S7 requires
From `doc/strategy/roadmap/stories/v2.21-s7.md`, S7 closes only when all of these are true:

1. Docs publish the support matrix, runtime tiers, install paths, demo commands, storage locations, manual verification, update/uninstall behavior, and unsupported features.
2. CLI, CaseOps, audit, replay, metrics, and diagnostics visibly expose platform tier and degraded guarantees.
3. Consumer macOS/Windows modes are documented as paper/sandbox/no-live-effect with live execution disabled.
4. Privacy defaults are documented: installer telemetry disabled unless later explicitly approved.
5. Evidence artifacts are linked: support matrix, version samples, doctor samples, installer verification samples, demo output, audit JSONL, replay capsule, blocked-flow output, conformance result.

  - `src/tickoni/demo/*`

  - `src/tickoni/schema/audit/audit.zig`
  - `src/tickoni/codec/audit/jsonl.zig`

### Gaps that block closure
1. **Command contract drift**
   - `tickoni --version` and `tickoni doctor` are the roadmap contract.
   - Current code splits those between `tickoni` and `tickoni-supervisor`.
   - `src/app/tickoni_cli/main.zig` implements `version`, not `--version`, and no `doctor`.
   - `src/app/tickoni/main.zig` implements `--version` and `doctor`, but under `tickoni-supervisor`.
2. **S7 docs are not yet written as user-facing closure docs**
   - No single support/retail-runtime guide covers install/update/uninstall/manual verification/storage locations/privacy defaults.
3. **Evidence is generated but not indexed**
   - S6 produces conformance artifacts, but there is no canonical S7 evidence index page linking all closure artifacts.
4. **CaseOps exposure is still declarative, not concretely documented in shipped surfaces**
   - `doc/knowledge/platform-tiers.md` says CaseOps should show tier/degradations, but there is no S7 closure note saying whether this is implemented now, deferred, or CLI-only for V2.21.
5. **Roadmap/epic closure docs remain open**
   - `doc/strategy/roadmap/epics/v2.21.md` still reads as backlog/open and must be reconciled after S7 artifacts land.

## 2. Scope Decisions To Make Before Editing

### Decision A: user-facing command contract
Pick one explicit contract and apply it everywhere:

- **Preferred:** make `tickoni` the documented product binary for `--version`, `doctor`, and demo entrypoints.
- **Fallback:** keep `tickoni-supervisor` as the implementation binary but document that clearly and stop claiming `tickoni doctor` already exists.

**Recommendation:** choose the preferred path. S7 is trust-surface closure; pushing retail users to a secondary `tickoni-supervisor` binary is needless product friction.

### Decision B: CaseOps scope for V2.21
Pick one honest stance and document it:

- **Option 1:** CLI/audit/replay expose tier now; CaseOps display is deferred.
- **Option 2:** minimal CaseOps metadata display lands now.

**Recommendation:** unless there is already hidden tkapi/UI work ready, choose Option 1 and state the deferral explicitly in docs and epic acceptance notes.

### Decision C: installer verification format
Pick one concrete deliverable for V2.21 evidence:

- checksums only
- checksums + attestation/signature placeholder doc
- checksums + signed release assets (if release automation already exists)

**Recommendation:** for V2.21, ship a documented checksum-based manual verification path unless release-signing infrastructure already exists.

## 6. Risks / Pitfalls

1. **Do not fake CaseOps support.** If V2.21 does not actually surface tier/degradation in tkapi/UI, document the deferral instead of claiming it exists.
2. **Do not leave split command semantics.** The user-facing product binary must match the docs.
3. **Do not treat design records as closure docs.** `platform-tiers.md` and `version-identity.md` are necessary but insufficient for S7.
4. **Do not claim signed releases unless they exist.** Checksums-only is acceptable if documented honestly.
5. **Do not bury evidence in CI logs only.** S7 needs stable linked artifacts in-repo.
6. **Do not broaden S7 into V2.22.** Keep Windows references only where the S7 story explicitly requires shared retail-mode documentation language.
