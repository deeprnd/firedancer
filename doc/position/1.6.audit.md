Implementation Plan: S6.TKMODL.3–11
The nine findings split naturally into five groups with a clear dependency order. Here's how to approach them:

Group A — Type System (S6.TKMODL.3 + S6.TKMODL.4)
Do together. These are a single refactor: rename the current transport type, hide it, and surface the governed type.

In schema.zig: rename ModelRequest → ProviderRequest; add full TkModlRequest struct with all governed fields (request_id, run_id/case_id, actor_id, actor_role, workflow, account_id, capability, policy fields, sampling limits, replay_mode, replay_substitution_id). Use [N]u8 fixed buffers consistent with the rest of the schema.
In backend.zig: make ProviderRequest a private (file-scope only) type; MockBackend/HttpBackend/Backend.call() accept only ProviderRequest. The TkModlRequest → ProviderRequest conversion is not the backend's job.
In mod.zig: stop re-exporting ModelRequest; export TkModlRequest instead.
In agent/mod.zig: the two hardcoded ModelRequest{...} literals at lines 50–56 and 113–119 become TkModlRequest{...} with all required fields populated. The agent no longer calls model_backend.call() directly — it will call the orchestrator (Group D).
Update all tests that construct ModelRequest directly.
Group B — Config + Validator (S6.TKMODL.5 + S6.TKMODL.6)
Do together. Pure data types and pure function, no side effects.

Add TkModlConfig to schema.zig: allowed_model_ids, live_provider_enabled, hard_max_context_tokens, hard_max_output_tokens, hard_max_retry_count, hard_timeout_ms, per_run_token_budget, provider_endpoint: [256]u8.
Add TkModlDecision tagged union to schema.zig with the 10 outcome tags from the spec (allow_live, allow_replay, deny_missing_scope, etc.).
Add validateTkModlRequest(config: TkModlConfig, req: TkModlRequest) TkModlDecision — pure function, one unit test per denial tag.
This is entirely additive; nothing breaks yet.

Group C — Builder + Transport Cleanup (S6.TKMODL.7 + S6.TKMODL.10)
Do together. The builder is small; the cleanup just removes the governance code that doesn't belong in HttpBackend.

Add buildProviderRequest(decision: TkModlDecision, req: TkModlRequest) ProviderRequest — only callable when decision is .allow_live; panics or returns an error otherwise. Located in the model tile, not backend.zig.
Strip from HttpBackend.call(): allowed_model_ids field, model allowlist loop, budget_id/policy_version empty checks. After cleanup, HttpBackend only constructs URL, serializes ProviderRequest, POSTs, parses WireResponse.
Strip from FixtureBackend.call(): model allowlist check, budget_id/policy_version/capability_envelope_id empty checks. Those validations move entirely to the orchestrator.
Update backend unit tests to reflect that FixtureBackend and HttpBackend no longer do governance — tests that check ModelNotAllowed/MissingBudgetId/MissingPolicyVersion from the backend now live in the orchestrator/validator tests instead.
Group D — Replay Backend (S6.TKMODL.8)
After Group A (needs ProviderRequest/TkModlRequest types).

Add ReplayBackend struct to backend.zig: holds a bounded table of replay_substitution_id → ProviderResponse; call() looks up by substitution_id or request hash, returns error.ReplaySubstitutionMissing if absent, never does HTTP.
Add .replay: ReplayBackend tag to the Backend union (alongside .mock, .fixture, .http). Update Backend.isEffectFree() to return true for .replay.
The .fixture backend can remain as-is (used by existing integration tests) — replay is the governed first-class path, fixture stays as a test convenience.
Group E — Orchestrator + Audit (S6.TKMODL.9 + S6.TKMODL.11)
Last, after A–D. Two related responsibilities, one logical commit boundary.

Orchestrator — new file src/tickoni/tiles/model/orchestrator.zig:


runTkModlRequest(config, backend, request) -> TkModlResult
Sequence: validate → decide live/replay → if live, build ProviderRequest, call backend, apply retry loop (up to config limit) → collect token_usage and latency → return TkModlResult with all audit-ready fields (request_hash, response_hash, replay_substitution_id, retry_count, latency_ms, outcome).

No basket, ticket, trading policy, or prompt authorization here.

Audit schema — extend ModelCallPayload in audit/schema.zig with four fixed-size fields:


actor_role: [16]u8,
workflow: [16]u8,
policy_decision_id: u64,
replay_substitution_id: u64,
Update buildAllowedTradeChain, buildOversizedTradeBlockedChain, and buildRestrictedInstrumentBlockedChain in investment_audit.zig to populate the new fields. The audit hash-chain is not broken because the schema version bump is not required for additive fixed fields (confirm with you before touching audit_schema_version).
