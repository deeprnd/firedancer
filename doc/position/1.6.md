Governed boundary items — none implemented
S6.TKMODL.3 — Rename ModelRequest to ProviderRequest: Not done. The transport request type is still ModelRequest (schema.zig:15), exported from mod.zig:6 and used across all callers. The spec said to rename it to ProviderRequest and keep wire structs private to backend.zig.

S6.TKMODL.4 — Governed TkModlRequest schema: Not done. No TkModlRequest type exists anywhere. The ModelRequest struct has budget_id, policy_version, capability_envelope_id added, but lacks the full governed contract: request_id, run_id/case_id, actor_id, actor_role, workflow, account_id, capability, policy_decision_id, max_context_tokens, max_output_tokens, retry_limit, timeout_ms, replay_mode, replay_substitution_id.

S6.TKMODL.5 — TkModlConfig: Not done. No config struct with model allowlist, hard token/retry/context limits, per-run budget, live_provider_enabled flag, or provider endpoint map.

S6.TKMODL.6 — validateTkModlRequest() validator: Not done. No pure function returning a TkModlDecision tagged union (allow_live, allow_replay, deny_missing_scope, deny_model_not_allowed, etc.). Validation is currently scattered: model allowlist check is in FixtureBackend.call() and HttpBackend.call(), budget check is in HttpBackend.call(), no retry/context/output limit enforcement exists anywhere.

S6.TKMODL.7 — Provider request builder: Not done. The WireRequest is built inline inside HttpBackend.call() (backend.zig:228). No standalone builder that requires a prior allow_live decision.

S6.TKMODL.8 — Replay substitution backend as first-class path: Partially done. FixtureBackend returns captured fixture data offline. But there is no replay_substitution_id lookup, no distinct .replay tag in the Backend union (only .mock, .fixture, .http), and missing substitution does not fail closed at the tkmodl level with a documented reason code.

S6.TKMODL.9 — runTkModlRequest orchestrator: Not done. runInvestmentAgent in agent/mod.zig:50 calls model_backend.call() directly with a hardcoded ModelRequest. There is no governed orchestrator that: validates the request, chooses live vs replay, builds provider request only for live, enforces retry limit, collects token usage and latency, and returns an audit-ready TkModlResult.

S6.TKMODL.10 — HttpBackend transport-only: Partially violated. HttpBackend.call() checks budget_id and policy_version (backend.zig:205) and has its own allowed_model_ids field — all governance concerns that the spec says belong in the orchestrator, not the transport layer.

S6.TKMODL.11 — Audit payload mapping: Partially done. model_call events have model_id, prompt_hash, response_hash, token_estimate, retry_count. Missing from the audit record per spec: replay_substitution_id, policy_decision_id, actor_role, workflow. The ModelCallPayload struct in the audit schema does not have these fields.

S6.TKMODL.12 — Replace symbolic hashes in fixtures: Partially done. Main replay_capsule.json has real numeric hashes for expected_basket_id, expected_proposal_hash, model expected_response_hash, and paper fill expected_response_hash. The oversized capsule has only the model hash. The restricted capsule has only the model hash. The audit_allowed_2000.jsonl still has symbolic string hashes everywhere.

S6.TKMODL.15 — Exec-facing demo command: Not done as specified. The spec requires a deterministic fixture-mode demo command with optional live mode, not a system test binary. The only candidate is v1_1_demo_live.zig which requires live llama.cpp.
