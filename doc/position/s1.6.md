# V1.1.S6 Tkmodl E2E Plan

## Scope

This plan closes `V1.1.S6: Investment demo and proof` for the active e2e demo
stage of `V1.1: Investment Intent To Paper Trade`.

The decision for this stage is:

- `tkmodl` is added now to the active V1.1 e2e demo topology.
- The normal deterministic demo lane must replay without a live model, broker,
  market, trading, payment, or execution effect.
- A separate live-local-model smoke lane may call a local OpenAI-compatible
  endpoint, but only through `tkmodl`.
- No agent, test, demo command, or fixture may call an LLM server directly.

The current model code is not sufficient as a `tkmodl` boundary because the
request is raw provider transport, the HTTP client owns too much policy
surface, and the topology does not yet make `tkmodl` an explicit runtime tile
for the demo.

## Success Criteria

V1.1.S6 is complete when:

- one local demo command or deterministic test fixture shows the AI
  infrastructure thesis becoming a basket, ticket, affordability check, paper
  execution summary, oversized block, and restricted-instrument block,
- all model work in that flow goes through `tkmodl`,
- `tkmodl` records policy version, budget id, model id, request hash, response
  hash or fixture reference, token usage, retry count, latency, and replay
  substitution id,
- the USD 2,000 allowed path, USD 25,000 oversized blocked path, and
  restricted-instrument path all emit audit-ready evidence,
- replay substitutes captured model and adapter outputs by hash and performs no
  live external calls,
- `just test-integration-tk` is deterministic and does not clone, download, or
  require a live LLM server,
- the live-local-model smoke path is explicit and opt-in.

## Topology Work

### S6.TKMODL.1: Add V1.1 E2E Topology

Add a topology constructor for the V1.1 demo rather than overloading the Phase 0
payment pipeline.

Required tiles:

- `tkings` - ingest tile: accepts the thesis/demo request, validates framing,
  assigns source identity and source offset, and applies ingress backpressure.
- `tknorm` - normalize tile: converts accepted thesis input into canonical,
  replay-stable investor intent facts.
- `tkdedu` - dedupe tile: rejects duplicate thesis/run inputs by stable
  idempotency key and content hash.
- `tkcase` - case/router tile: attaches the request to a deterministic case or
  synthetic run scope for shared policy, audit, model, adapter, and replay
  records.
- `tkpoly` - policy tile: evaluates finance-native capability envelopes for
  trading recommendation/proposal/paper placement scope and returns explicit
  outcomes.
- `tkaudt` - audit tile: owns append-only audit ordering, hash-chain records,
  and replay capsule sealing.
- `tkdisp` - dispatch tile: schedules bounded agent work for the scoped demo
  run after the event/case path is auditable.
- `tkagnt` - agent worker tile: runs the investment demo agent as a bounded
  proposal-first worker with no direct model, adapter, broker, shell, or
  unrestricted network access.
- `tkmodl` - model gateway tile: owns model-provider or local LLM access,
  allowlists, context limits, retry limits, token budgets, audit metadata, and
  replay substitution.
- `tktool` - tool broker tile: normalizes model-native function/tool requests
  into finance-native adapter request envelopes.
- `tkadpt` - adapter tile: serves scoped paper-trading fixtures or signed
  adapter calls for quotes, portfolio reads, and paper fill results.
- `tkrepl` - replay tile: replays the run with external effects disabled and
  substitutes captured model and adapter outputs by hash.
- `tkmetr` - metrics tile: exports queue, tile, model, adapter, policy, replay,
  and demo health metrics.
- `tkdiag` - diagnostics tile: exports process, queue, crash, denial, replay,
  and supervisor diagnostics for the demo topology.

Required reliable links:

- `tkings_tknorm`
- `tknorm_tkdedu`
- `tkdedu_tkcase`
- `tkcase_tkpoly`
- `tkcase_tkdisp`
- `tkdisp_tkagnt`
- `tkagnt_tkmodl`
- `tkagnt_tktool`
- `tktool_tkadpt`
- `tkpoly_tkaudt`
- `tkmodl_tkaudt`
- `tktool_tkaudt`
- `tkadpt_tkaudt`
- `tkagnt_tkaudt`
- `tkaudt_tkrepl`

Telemetry links to `tkmetr` and `tkdiag` may be counted-loss links if loss is
visible.

Verification:

- topology validation fails closed on invalid link indices and non-power-of-two
  depths,
- a topology unit test confirms `tkmodl` is present in the V1.1 topology,
- a topology unit test confirms the deterministic event path still begins
  `tkings -> tknorm -> tkdedu -> tkcase -> tkpoly -> tkaudt`.

### S6.TKMODL.2: Preserve Phase 0 Topology

Keep `paymentPipeline()` as the Phase 0 payment pipeline. Do not silently insert
agent/model/tool tiles into that constructor.

Verification:

- existing Phase 0 topology tests still pass,
- a new V1.1 topology test proves the e2e demo path is separate and explicit.

## Break Down The Boundary/Transport Split

The phrase "split `tkmodl` boundary from HTTP transport" is too broad. Implement
it as the following small tasks.

### S6.TKMODL.3: Rename Current Model Request To Provider Request

The current `ModelRequest` is an OpenAI-compatible provider request, not the
governed `tkmodl` request.

Change:

- rename the transport-facing request type to `ProviderRequest`,
- rename the transport-facing response type to `ProviderResponse` if needed,
- keep provider wire structs private to `backend.zig`,
- update `MockBackend`, `HttpBackend`, and `Backend.call()` to accept only
  provider-level inputs.

Do not add policy checks in this task.

Verification:

- existing mock backend tests still pass after rename,
- no test constructs an HTTP backend with a governed `tkmodl` request.

### S6.TKMODL.4: Add Governed Tkmodl Request Schema

Add a separate `TkModlRequest` type that is the tile boundary contract.

Required fields:

- `request_id`
- `run_id` or `case_id`
- `actor_id`
- `actor_role`
- `workflow`
- `account_id`
- `capability`
- `capability_envelope_id`
- `policy_version`
- `policy_decision_id`
- `budget_id`
- `model_id`
- `messages`
- `sampling`
- `max_context_tokens`
- `max_output_tokens`
- `retry_limit`
- `timeout_ms`
- `replay_mode`
- `replay_substitution_id`

Use bounded buffers or bounded slices consistent with the existing Zig schema
style. Avoid stringly-typed open-ended maps.

Verification:

- missing `policy_version`, `budget_id`, capability scope, or model id is
  rejected,
- unsupported capability is rejected,
- oversize prompt, message count, or max-output request is rejected,
- `TkModlRequest` can be converted to `ProviderRequest` only after validation.

### S6.TKMODL.5: Add Tkmodl Policy Config

Add a `TkModlConfig` owned by the model tile boundary.

Required fields:

- enabled providers,
- model allowlist,
- provider endpoint mapping,
- default timeout,
- hard max timeout,
- hard max retry count,
- hard max context tokens,
- hard max output tokens,
- per-run token budget,
- per-request token budget,
- replay enabled flag,
- live provider enabled flag.

Do not read provider policy from environment variables inside the request path.
Environment parsing may happen at startup or in test setup, then produce an
explicit config value.

Verification:

- unknown model id fails closed,
- disabled provider fails closed,
- request retry limit greater than config hard limit fails closed,
- request context/output limit greater than config hard limit fails closed,
- live model call is denied when `live_provider_enabled` is false.

### S6.TKMODL.6: Add Request Validator

Add a pure validation function:

```text
validateTkModlRequest(config, request) -> TkModlDecision
```

Decision outcomes:

- `allow_live`
- `allow_replay`
- `deny_missing_scope`
- `deny_model_not_allowed`
- `deny_budget_exhausted`
- `deny_context_limit`
- `deny_output_limit`
- `deny_retry_limit`
- `deny_live_provider_disabled`
- `deny_replay_substitution_missing`

This validator must not perform HTTP, filesystem, model, or audit side effects.

Verification:

- each denial has a unit test,
- allowed live and allowed replay decisions have unit tests,
- denied decisions produce stable, auditable reason codes.

### S6.TKMODL.7: Add Provider Request Builder

Add a small function that converts a validated `TkModlRequest` into a
`ProviderRequest`.

Rules:

- it requires an `allow_live` decision,
- it clamps nothing silently,
- it carries the exact model id, messages, sampling, and output limit that were
  validated,
- it does not read config or environment directly.

Verification:

- conversion fails if validation did not allow live,
- generated provider request matches the governed request exactly.

### S6.TKMODL.8: Add Replay Substitution Backend

Add replay as a first-class path, separate from `.mock`.

Required behavior:

- replay lookup uses `replay_substitution_id` or request hash,
- replay returns captured model content, model id, token usage, finish reason,
  latency, response hash, and fixture reference,
- replay never calls HTTP,
- missing substitution fails closed.

Verification:

- replay path succeeds with a captured fixture,
- replay path fails when substitution id is missing,
- replay path fails when captured request hash does not match.

### S6.TKMODL.9: Add Tkmodl Orchestrator

Add the tile-facing orchestration function:

```text
runTkModlRequest(config, backend, audit_sink, request) -> TkModlResult
```

Responsibilities:

- validate the governed request,
- choose live or replay from the validation decision,
- build provider request only for live calls,
- call provider transport only after validation,
- apply retry limit,
- collect token usage and latency,
- produce audit-ready request and response references,
- return a bounded result to the caller.

Non-responsibilities:

- basket construction,
- trading policy,
- adapter policy,
- ticket execution,
- prompt authorization by text instruction.

Verification:

- live path never executes after a deny decision,
- replay path never executes HTTP,
- retry count cannot exceed config,
- result includes audit fields needed by `tkaudt`.

### S6.TKMODL.10: Keep HttpBackend Transport-Only

After the orchestrator exists, keep `HttpBackend` small.

Allowed in `HttpBackend`:

- URL construction from configured endpoint,
- OpenAI-compatible JSON serialization,
- HTTP call,
- OpenAI-compatible response parsing,
- provider network error mapping,
- raw provider metadata return.

Not allowed in `HttpBackend`:

- capability checks,
- model allowlist,
- budget checks,
- replay substitution,
- audit record construction,
- environment parsing,
- fallback to mock.

Verification:

- backend unit tests only cover provider request/response behavior,
- governance tests target the `tkmodl` validator and orchestrator.

## Implementation Order

1. Add V1.1 topology with `tkmodl` active and preserve Phase 0 topology.
2. Rename raw model transport types to provider-level names.
3. Add governed `TkModlRequest`, `TkModlConfig`, and validation outcomes.
4. Add provider request builder.
5. Add replay substitution backend.
6. Add `tkmodl` orchestrator and audit-ready result type.
7. Keep `HttpBackend` transport-only and remove policy-shaped behavior from it.
8. Update deterministic integration tests to use `tkmodl` replay substitution.
9. Add missing oversized and restricted audit/replay fixture coverage.
10. Move live llama.cpp/Hugging Face setup to explicit smoke recipes.
11. Add exec-facing V1.1.S6 demo command.
12. Run `just test-unit-tk`, `just test-integration-tk`, and the explicit smoke
    recipe only when live model prerequisites are intentionally present.

## Non-Goals

- Do not give agents direct model-provider, LLM-server, GPU, shell, or network
  access.
- Do not make prompt text a policy boundary.
- Do not make the deterministic integration lane depend on live model
  availability.
- Do not connect to a real broker or trading API in V1.1.S6.
- Do not introduce TigerBeetle or `tkexec` execution for the paper demo.
- Do not hide failed policy, budget, replay, or provider decisions behind a
  mock fallback.

## Open Design Notes

The e2e demo needs `tkmodl` active now, but active does not mean all model work
belongs in the deterministic financial event critical path. The correct shape
is still:

```text
tkings -> tknorm -> tkdedu -> tkcase -> tkpoly -> tkaudt
tkcase -> tkdisp -> tkagnt -> tkmodl
tkagnt -> tktool -> tkadpt
all material boundaries -> tkaudt
tkrepl substitutes captured model and adapter outputs
```

That keeps the demo credible as an AI harness while preserving the architecture
rule that model output is captured, audited, and replay-substitutable rather
than trusted as deterministic runtime truth.
