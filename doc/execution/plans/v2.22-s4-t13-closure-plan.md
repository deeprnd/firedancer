## Upstream Merge & Conflict Reduction Plan

The branch has ~100 commits ahead of main. Upstream (`firedancer-io/firedancer`) is actively changing `main`. Every merge will touch:

### Highest Conflict Zones

1. **Build system** (`build.zig`, `Local.mk`, `justfile`, `*.mk` files) — multiple commits on both sides
2. **Shim files** (`src/tickoni/c_abi/shim/*.c`) — platform-specific branches overlap with Firedancer changes
3. **CI files** (`.github/workflows/*.yml`, Windows scripts) — both branches add CI lanes
4. **Topo files** (`src/disco/topo/*.c`) — per-platform split overlaps with Firedancer topo changes
5. **Tile threading** (`src/util/tile/*.c`) — per-platform split

### Conflict Reduction Strategy

1. **Rebase, don't merge.** Keeps history linear and makes conflicts easier to resolve:
   ```bash
   git fetch upstream
   git rebase upstream/main
   ```

2. **Merge upstream changes in small batches.** Pull when 5-10 commits ahead. Resolve immediately while you know what's changing.

3. **Isolate Tickoni-owned from Firedancer-owned files.** Check if upstream changes touch:
   - `src/disco/topo/` — per-platform split
   - `src/util/tile/` — tile_threads platform split
   - `build.zig` — Tickoni build hooks
   - `Local.mk` files — Tickoni object additions

4. **Enable `git rerere`** for recurring conflicts:
   ```bash
   git config rerere.enabled true
   ```

5. **Use a "merge window" approach.** Before S4 closure: freeze branch, pull upstream, resolve all conflicts, run full gate, submit merge PR.

### PR Target

Per the established rule: PRs go to `deeprnd/tickoni`, not `deeprnd/firedancer` nor `firedancer-io/firedancer` (upstream). The `win-runtime` branch merges into the `deeprnd/tickoni`.
