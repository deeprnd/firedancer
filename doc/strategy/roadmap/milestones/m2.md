# M2: Governed Harness Runtime

## Description

M2 makes the tile runtime production-credible:

```text
real processes -> agent limits -> tool boundary -> model limits
```

Tiles move from in-process threads to supervisor-managed processes over
Firedancer shared-memory links. Agent runs gain a formal lifecycle with
auditable terminal states. The tool broker closes the bypass path between model
output and adapters. Model call and token-budget limits become enforceable
policy events rather than advisory counters.

## Why This Is A Milestone

M1 establishes the investing demo on logical tile boundaries. M2 makes those
boundaries real and enforced.

It deserves milestone status because it changes the harness from a
demo-credible scaffold into a runtime where:

- a crashing tile cannot corrupt a sibling process
- an agent run that hits its step or budget limit halts with an audit record
  instead of panicking or looping
- a model-native function call and an MCP-style request for the same tool
  produce the same normalized record at the adapter boundary
- per-role and per-case model-call limits are auditable policy events, not
  silent truncations

These properties are prerequisites for the proof and trust surfaces in M3.

## Completion Signal

M2 is complete when integration tests confirm: one OS process per tile over
shared-memory links, step-limit-exceeded and budget-exhausted runs produce
audit records, tool bypass is denied, and per-role model-call limits halt that
role without affecting others.
