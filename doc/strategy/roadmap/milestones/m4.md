# M4: Portfolio Management And Valuation Queue

## Description

M4 delivers the end-to-end consumer investing surface that turns Tickoni's governed
event runtime into a demonstrable product. Users create and manage portfolios, view
exposure by sector and industry through pie charts rendered from auditable holding
records, receive deterministic rebalance suggestions, maintain watchlists with
automatic Damodaran valuation via V3.22, and select which LLM model powers each
investigation. Milestone M4 comprises two epics: V4.1 (Portfolio Management And
Valuation Queue) and V4.2 (Model Selection And Governance).

```text
portfolio intent -> policy gate -> auditable exposure -> valuation evidence
```

## Why This Is A Milestone

M4 closes the qualitative gap between "Tickoni is a governed event engine with a
valuation calculator" and "Tickoni is a consumer investing product with complete
auditability." Three prerequisites from M3 converge here: the proven runtime
ingestion-normalization-dedupe-audit path, the V3.22 Damodaran valuation engine,
and the tamper-evident replay discipline. M4 wires all three together into a visible
loop where a user action (add a holding) produces an auditable event, triggers a
valuation, and surfaces a policy-checked proposal. No prior milestone can demonstrate
this full loop because none of them owned portfolio state or the valuation queue.

M5 (Approved Payment And Broker Sandbox) depends on M4 because M4 establishes the
portfolio state model and rebalance proposal pattern that payment/broker execution
later operates on — rebalance suggestions become approved mutations only after M4's
proposal surface exists.

This earns milestone status because it crosses from "runtime with a calculator" into
"a complete, visible, auditable portfolio lifecycle" — the first consumer-facing
increment that proves Tickoni's policy and audit discipline applies to investing,
not just to payments and transfers.

## Completion Signal

A user can run a deterministic demo with a fixture portfolio (AAPL 50 shares, MSFT
30 shares, TSLA 10 shares, NVDA 20 shares, USD 5,000 cash), see exposure charts
render Technology 82% (drift +42%), receive a `portfolio.rebalance.propose` envelope
for drift correction, add AMZN to the watchlist, and see AMZN complete a Damodaran
valuation with intrinsic value range and Monte Carlo CI — all replayable from captured
inputs with no external side effects.

Integration tests confirm:
- Portfolio CRUD mutations flow through the governed event path and are reconstructable
  from the audit chain.
- Exposure charts are deterministic functions of auditable holding records.
- Rebalance suggestions are computed by deterministic exposure diff, not agent output.
- Watchlist tickers enter the V3.22 valuation queue with full capability checks.
- Model tier selection (V4.2) is stored as `tkmodl` capability scope and enforced.
- Replay produces byte-identical output with substituted model and adapter outputs.
