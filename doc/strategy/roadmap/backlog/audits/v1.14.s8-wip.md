           - grep for 'fd_topob' in run.c returns NOTHING
           - grep for 'fd_topob' in run1.c returns NOTHING

       1b. fd_topo_run_tile() calls only standalone infrastructure, no fd_topob.c:
           - fd_topo_join_tile_workspaces() -> fd_topo.c (NOT fd_topob.c)
           - fd_topo_fill_tile() -> fd_topo.c (NOT fd_topob.c)

       1d. fd_topo_run_single_process() HAS a hard coupling to fdctl:
           - Signature: fd_topo_run_single_process(topo, agave, uid, gid, fd_topo_run_tile_t (*tile_run)(fd_topo_tile_t const*))
           - Calls tile_run(tile) to get the strategy struct per-tile via fdctl_tile_run() + TILES[]

           - MITIGATION: Tickoni callbacks only use the generic fields

       What the audit DIDN'T check — and what we checked next:

       How does Tickoni construct an fd_topo_t? Can we use fd_topob.c?

       We traced every fd_topob function to see if the builder actually drags in Solana semantics.

       fd_topob.c functions and their Solana content:

       fd_topob_new() — memset to zero, sets app_name, page sizes, agave_affinity_cnt=0
         → NO SOLANA. Generic bootstrap.

       fd_topob_wksp() — appends workspace entry, copies name, sets id/core_dump_level
         → NO SOLANA. Generic workspace declaration.

       fd_topob_obj() / fd_topob_obj_named() — creates named objects in workspaces
         → NO SOLANA. Generic object management.

       fd_topob_link() — creates link entry, creates mcache/dcache objects, sets depth/mtu/burst
         → NO SOLANA. Generic link declaration.

       fd_topob_tile() — creates tile entry, sets name/kind_id/cpu_idx/in_cnt/out_cnt,
         creates tile/metrics/keystream objects.
         Takes is_agave, uses_id_keyswitch, uses_av_keyswitch as int params.
         You pass 0 for all three. The fields just get stored in the struct;
         nothing else in the system reads them during construction.
         → SOLE SOLANA TOUCH: 3 int params you set to 0.

       fd_topob_tile_in() — wires links to tiles, sets in_link_id[]/reliable/poll arrays,
         creates fseq objects, declares read-only access on link mcache/dcache
         → NO SOLANA. Generic link wiring.

       fd_topob_tile_out() — wires tiles to links, sets out_link_id[] array,
         declares read-write access on link mcache/dcache
         → NO SOLANA. Generic link wiring.

       fd_topob_tile_uses() — declares tile→object access mode (read-only or read-write)
         → NO SOLANA. Generic object access.

       fd_topob_finish() — validates: workspace uniqueness, link reachability,
         no duplicate in/out links, no self-loops, exactly one producer per link,
         at least one consumer per link, workspace id consistency.
         → NO SOLANA. Pure structural validation.

       fd_topob_auto_layout() — hardcodes Solana tile name arrays (FLOATING[], STARTUP[],
         ALWAYS[], CRITICAL_TILES[]) and reserves Agave cores via reserve_agave_cores param.
         → SOLANA NAME ARRAYS ONLY. The algorithm itself is generic:
           1. fd_topo_cpus_init() scans /proc/cpuinfo + sysfs → physical cores, NUMA nodes, HT siblings, online status
           2. Assigns tiles to CPUs by iterating 4 name-based priority phases in order:
              ALWAYS → STARTUP → POST_START → FLOATING (tiles not matching any phase get warning, left floating)
           3. CRITICAL tiles excluded from HT-pair scheduling (latency-sensitive tiles must not share a hyperthread)
           4. reserve_agave_cores reserves leftover physical cores for Agave
           5. tile->cpu_idx set per-tile before fd_topo_run_tile() reads it

         The algorithm (NUMA scanning, HT-pair handling, priority ordering, floating fallback)
         is generic and should be reused identically. Only the name arrays are Solana.

         REIMPLEMENTATION PLAN:
         - Extract and reuse the algorithm from fd_topob_auto_layout() as-is:
           fd_topo_cpus_init() (generic sysfs scan)
           auto_tile_cpu() (NUMA ordering, HT-pair exclusion)
           auto_layout_cpus() (4-phase priority loop with cpu_bv bitset)
         - Replace name arrays with Tickoni tile groups:
           CRITICAL: tiles that must not share HT pairs (e.g., tkings, tkrnorm — deterministic critical path)
           ALWAYS: tiles always running (e.g., tkdedu, tkpoly, tkaudt — continuous event pipeline)
           FLOATING: tiles that can be kernel-scheduled (e.g., tkmetr, tkdiag, tkdisp — monitoring)
           STARTUP/POST_START: Tickoni startup phases (bootstrap → steady-state)
         - Omit reserve_agave_cores entirely (no Agave)
         - Pass 0 or NULL for the parameter

       fd_topob_tile_priority_type() — matches tile names against hardcoded Solana arrays.
         → SOLANA NAME ARRAYS ONLY. Algorithm is the same for-each strcmp loop.
         → REIMPLEMENT with Tickoni tile groups instead (same pattern, different names).

       VERDICT: fd_topob.c CAN be used. It's not Solana-shaped — it's a generic topology builder
       that happens to have two Solana-specific functions (auto_layout, tile_priority_type)
       and three trivial int parameters on fd_topob_tile(). The algorithm inside both functions
       (NUMA CPU scanning, HT-pair handling, 4-phase priority ordering) is generic and should be
       reimplemented with Tickoni tile groups. The rest of fd_topob.c is purely generic.

       Usage pattern:
       1. fd_topob_new(topo, "tickoni") — allocate and zero the topology
       2. fd_topob_wksp() for each workspace (tickoni_wksp, metrics_wksp, etc.)
       3. fd_topob_link() for each inter-tile link
       4. fd_topob_tile(topo, name, wksp, metrics_wksp, cpu_idx, 0, 0, 0) for each tile
         - Pass 0 for is_agave, uses_id_keyswitch, uses_av_keyswitch
         - Keyswitch objects (128B shmem each with state machine: SWITCH_PENDING→COMPLETED/FAILED)
           are generic — can be repurposed for auth token refresh (GCP/GCS OAuth, AWS creds,
           LLM provider API keys, adapter secrets) by writing new bytes to bytes[64] and
           signaling state transition. For Tickoni tiles that need no runtime auth rotation, pass 0.
       5. fd_topob_tile_in() / fd_topob_tile_out() to wire links to each tile
       6. fd_topob_finish(topo) for validation
       7. fd_topo_cpus_init() → fd_topob_auto_layout_cpus() → replace Solana name arrays with Tickoni groups
          or assign cpu_idx manually before step 4
       8. Pass topo->tiles[] and topo directly to fd_topo_run_tile()

       The Solana union fields (xdp, sock, gossip, quic, etc.) are zeroed by fd_topob_new()'s
       memset and are never read in the core launch path (verified in fd_topo_run.c lines 49-140:
       reads name, kind_id, cpu_idx, allow_shutdown, metrics — none are Solana union fields).
       fd_topo_run_single_process() reads is_agave (lines 326, 335) but Tickoni doesn't use
       single-process mode — it uses per-process execve which calls fd_topo_run_tile() directly.

       This resolves the topology construction problem cleanly:
       - Use fd_topob.c with 3 params set to 0, 2 functions reimplemented with Tickoni names
       - Extract and reuse the CPU placement algorithm (NUMA scanning, HT-pair handling, priority ordering)
       - Keyswitch objects available as generic 128B auth-refresh mechanism or pass 0 if not needed
       - No separate builder, no fork, no manual struct population
       - Topology validation happens for free (fd_topob_finish checks)
       - No Solana semantics leaked into Tickoni product code
