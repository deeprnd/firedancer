# Release M1: Safe Money Decisions

## Tag: v1.0.0-m1

## Summary

M1 is the moment Tickoni stops being a runtime proof and starts being a product.

A user can express an investment thesis in plain English. Tickoni turns it into a
bounded, explainable, policy-gated, and fully auditable paper trade — with
cash impact, portfolio exposure, and drift monitoring before and after the
decision. Nothing executes live. Nothing can be bypassed. Everything is
replayable.

The M1 release delivers:

- **Investment intent to paper trade** — V1.1: thesis input, instrument
  classification, basket construction, affordability checks, trade tickets,
  and paper execution inside hard guardrails.
- **Portfolio and cash impact loop** — V1.3: before/after portfolio and cash
  views, thesis cards, proposal cards, drift alerts, rebalance suggestions,
  and a general instrument classification contract.
- **Release closure with no-bypass enforcement** — V1.11: governed tile
  topology (`tkcase`, `tkdisp`, `tkagnt`, `tkmodl`, `tktool`, `tkadpt`,
  `tkaudt`, `tkrepl`), full audit trail, replay from captured inputs, tamper
  detection, and direct-placement denial.
- **Firedancer process and shared-memory topology** — V1.14: supervisor-managed
  processes over Tango `mcache`/`dcache` shared-memory links, CPU placement
  with exclusive and reusable shared-core layouts, crash containment, and
  source-tree normalization.

## What Changed

### Investment Flow

- Natural-language thesis input normalized into structured investor intent
  (theme, notional, asset classes, markets, sectors, risk preferences).
- Deterministic demo fixtures for AI infrastructure, US dividends, cyber
  security, broad market, and cash preservation themes.
- General instrument classification contract replacing packed boolean
  representations — stock, ETF, bond, option, future, fund, and token types
  distinguished from economic exposure (equity, fixed income, commodity, FX,
  crypto, cash).
- Sector, industry, and theme classification stored as bounded lists with
  canonical taxonomy IDs and version identifiers for audit stability.
- Basket construction from thesis intent and instrument catalog with scope
  enforcement (US market, NYSE/NASDAQ, equity/ETF, restricted-instrument
  denylist, concentration rules).
- Explainability strings for every instrument inclusion and rejection.
- Demo portfolio schema with cash, buying power, holdings, open orders, and
  daily/monthly notional tracking.
- Affordability engine computing max affordable amount, remaining daily/monthly
  notional, and explicit blocked/restricted reasons.
- Trade ticket conversion with line-item orders, market/limit order types,
  buy/sell preview, and guardrail validation.
- Paper execution bound to validated tickets with proposal hash, capability
  envelope, and policy decision — no bypass possible.

### Portfolio and Cash Impact

- Before/after portfolio view showing sector exposure, asset class allocation,
  and ticker concentration changes.
- Before/after cash and pending-obligation view including payment proposals
  alongside investment trades.
- Thesis card schema persisting thesis state, linked positions, target and
  current exposure, and drift status.
- Money proposal card schema tracking beneficiary, rail, amount, approval
  state, expiry, and evidence hash.
- Thesis drift conditions: allocation breach, sector exposure breach,
  concentration breach, instrument ineligibility, buying power change.
- Payment drift conditions: retry window expired, beneficiary limit changed,
  evidence expired, approval expired/revoked, cash buffer breached.
- Deterministic rebalance suggestions and payment-proposal updates —
  no autonomous execution.

### Governance and Safety

- Governed tile topology separating V1.11 investment path from Phase 0
  payment pipeline (`paymentPipeline()` untouched).
- `tkmodl` boundary with `TkModlRequest` and `TkModlConfig` schemas —
  fail-closed for unknown models, disabled providers, and oversize requests.
- Model replay substitution without live provider calls.
- Unconfigured GPU providers fall back to stub with no silent API call.
- Paper placement bound to validated ticket, proposal hash, capability
  envelope, policy decision, account, environment, and deterministic action ID.
- Direct paper-placement bypass denial verified.
- Save-as-proposal path for tickets that pass validation but need human approval.

### Platform and Runtime

- Supervisor-managed tile processes replacing in-process threads.
- Firedancer Tango `mcache`/`dcache` shared-memory links replacing heap-backed
  correctness queues.
- `fseq`/`fctl`-backed reliable flow control on correctness-bearing links;
  telemetry links explicitly declared lossy with counted drops.
- `cnc`-backed tile lifecycle (boot, heartbeat, halt, fail state).
- Tickoni-owned CPU placement policy supporting exclusive, shared, and
  floating modes — no hard "one tile per core" requirement.
- Malformed or unavailable CPU IDs fail closed.
- Accidental CPU oversubscription fails closed when sharing is not declared.
- Crashed tile reported by identity; sibling state not corrupted; supervisor
  follows crash-only shutdown or restart behavior.
- Demo and replay output matching across exclusive-core and shared-core CPU
  configs.
- Source-tree normalization: `schema.zig` renamed to `types.zig`/`messages.zig`
  across tiles; protobufs unified under `src/tickoni/schema/proto/`; fixtures
  moved out of canonical schema paths; demo code separated from runtime;
  codec implementations isolated under `src/tickoni/codec/`.

### Audit and Replay

- Full audit trail for every capability decision, model call, tool call,
  adapter call, policy outcome, and paper execution.
- Replay reconstructed from captured inputs with model and adapter
  substitutions — no live external effects.
- Deliberate tamper produces first-divergence field and sequence report.
- Replay capsules versioned with schema, catalog, taxonomy, and policy
  versions; unsupported schema versions rejected explicitly.
- Classification evidence hashes stable across source ordering.
- Audit output exposes enough classification context to explain allow or deny
  without re-inference from ticker or label.

## Non-Goals

This release explicitly does not include:

- Live brokerage order placement
- Margin trading, options, futures, leveraged/inverse ETFs, or crypto execution
- Production market-data dependency
- Autonomous trading or portfolio rebalancing
- Per-role or per-case model-call limits or budget-exhaustion terminal states
- MCP-compatible tool dispatch normalization
- Content-addressed evidence store or replay capsule integrity hashes
- CaseOps UI (V1.19)

## Tile Topology

V1.11 topology (investment path):

```
tkings → tknorm → tkdedu → tkcase → tkpoly → tkaudt
                                    ↘ tkdisp → tkagnt
                                    ↘ tkmodl
                                    ↘ tktool → tkadpt
                                    ↘ tkrepl
                                    ↘ tkmetr / tkdiag
```

V1.14 topology converts all tile threads to supervisor-managed processes over
Firedancer Tango shared-memory links while preserving the same logical flow.

## Policy Outcomes Used

| Outcome | Meaning |
| --- | --- |
| `allow` | Agent may perform scoped action |
| `deny` | Action outside scope or blocked by policy |
| `require_approval` | Valid as proposal but needs human approval |
| `require_more_evidence` | Cannot proceed until evidence attached |
| `escalate` | Case moves to human or specialist queue |

## Exit Criteria

- A user can run deterministic fixtures for V1.1 and V1.3 and get replayable
  evidence for allowed, blocked, resized, approval-required, evidence-required,
  and escalated investing flows.
- One offline command reproduces the full USD 2,000 allowed / USD 25,000 blocked
  / restricted instrument denied / bypass denied / replay success / tamper
  detection sequence.
- No paper action can bypass validated ticket, policy, capability, or action
  identity.
- Replay performs no live model, broker, market, trading, payment, or execution
  effects.
- `just test-unit-tk` passes with no unexpected skips.
- `just test-integration-tk` passes offline.
