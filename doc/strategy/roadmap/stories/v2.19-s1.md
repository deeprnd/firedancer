# V2.19.S1: Terminal Shell, Navigation, And Command Bar

**Status:** Backlog
**Epic:** #V2.19
**Parent roadmap item:** V2.19: Tickoni Terminal CaseOps UI
**Labels:** `story`, `operations`, `enhancement`

Deliver the terminal shell, visual system, keyboard navigation, command bar,
and panel layout that all V2.19 screens share.

## Product Outcome

Operators can move through Tickoni's money-control workspace with a dense,
stable, keyboard-first UI that feels like a financial terminal while centering
policy, consequence, audit, and replay.

## User Story

As a CaseOps operator, I want a compact terminal workspace with command-driven
navigation, so that I can inspect money decisions quickly without losing the
policy and proof context.

## Scope

- In scope: terminal frame, status strip, navigation bar, command bar,
  responsive panel grid, status colors (green=allow/pass, red=deny/failed,
  amber=approval required/evidence missing, blue=selected, gray=unavailable),
  loading/error/empty states, keyboard focus model, and the ten top-level
  navigation tabs: INTENT, SAFE-ACTION, PORTFOLIO, PAYMENTS, CASEOPS, AUDIT,
  REPLAY, CAPABILITIES, ADAPTERS, HEALTH.
- Out of scope: financial policy logic, live adapter calls, execution actions,
  domain-specific panels (investment workbench, payment guard, impact view,
  audit black box, capability panels), and any direct runtime mutation.

## Preconditions And Assumptions

- CaseOps remains an attached UI over `tkapi`.
- UI state is presentation state only; runtime truth remains in Tickoni tiles
  and artifacts.
- Bloomberg-style density is a visual reference, not permission to add
  trading-gamification concepts.
- The terminal uses a dark or near-black workspace, condensed monospace for
  numbers, compact sans for labels, thin gray-blue panel borders, and minimal
  motion limited to ticker strips, queue counters, adapter pings, replay
  status, and policy gate transitions.

## Acceptance Criteria

- [ ] Given deterministic fixture data, when the terminal loads, then the
      status strip, navigation bar, command bar, and empty panels render without
      overlapping text at supported desktop and narrow widths.
- [ ] Given a known command such as `/show policy`, when the operator submits
      it, then focus moves to the related panel or shows a deterministic
      command result.
- [ ] Given an unknown command, when the operator submits it, then the terminal
      fails closed with a non-mutating error message and no runtime action.
- [ ] Given keyboard navigation, when the operator tabs or uses function keys
      between panels, then focus highlight is visible and keyboard shortcuts are
      documented.

### Conditional Acceptance

**Financial capability and policy**

- [ ] N/A - shell story displays no policy decisions beyond shared status badge
      containers.

**Audit and replay**

- [ ] N/A - shell story reserves panel slots but does not define audit or
      replay data contracts.

**Runtime topology and tile ownership**

- [ ] N/A - no tile ownership, queue, workspace, or link changes.

**Model, tool, adapter, or execution boundary**

- [ ] Unknown commands cannot call model, tool, adapter, execution, shell, or
      network paths directly.

**CaseOps API or UI**

- [ ] UI routes and commands are documented as CaseOps presentation commands,
      not financial capability names.

## Evidence Plan

- Demo or command: local UI storybook, preview, or app route with shell fixtures.
- Tests: focused keyboard navigation, command parser, and responsive rendering
  checks.
- Fixtures or samples: terminal shell fixture with status, policy version, and
  environment badges.
- Audit/replay evidence: N/A - shell only.
- Blocked-flow evidence: unknown command fixture.
