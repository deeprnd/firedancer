# V1.14: Firedancer Process And Shared-Memory Topology

**Status: Planned · Milestone: M1**

**Epic:** #TBD · **Issue:** #TBD

Replace in-process tile threads with supervisor-managed processes communicating
over Firedancer Tango shared-memory links. V1.11 runs tiles as in-process
threads behind a logical topology boundary; this increment makes process
isolation real and is a prerequisite for crash-propagation guarantees,
seccomp/Landlock sandboxing, and production deployment.

Extracted from V1.11.S6.

---

## Product Intent

V1.11 established a governed tile topology with audit, replay, and no-bypass.
The tile boundaries are logical: tiles share a process and communicate over
heap-backed queues. V1.14 converts every tile into a supervisor-managed process
and replaces heap-backed queues with Firedancer Tango `mcache`/`dcache`
shared-memory links. Demo and replay output must be identical across both
exclusive-core and shared-core CPU configs.

## User Story

As a Tickoni operator, I can run each tile as an isolated supervisor-managed
process over Firedancer shared-memory links, so that tile crashes are contained,
CPU placement is validated, and tile boundaries are real rather than logical.

## What The Operator Sees

- process list with one entry per tile, each managed by the supervisor
- shared-memory workspace identifiers per inter-tile link
- CPU affinity assignments per tile in the supervisor configuration
- link health metrics (depth, overrun count, drop count) per link
- crash report with the identity of the failing tile, isolated from sibling tiles

## Success Demo

- [ ] Supervisor starts each tile as a separate process; `ps` shows one process per tile.
- [ ] Events cross tile boundaries through Tango shared-memory links; no heap queue is present.
- [ ] CPU placement fails closed when a configured CPU id is unavailable.
- [ ] A crashing tile does not corrupt or stall a sibling tile's process.
- [ ] Demo and replay output matches under exclusive-core and shared-core configs.

## Release Gate

- `just test-unit-tk` passes with no unexpected skips
- `just test-integration-tk` passes offline against local mocks
- integration test shows tiles as isolated processes over shared-memory links
- CPU placement fails closed for malformed or unavailable CPU ids
- demo and replay results are byte-identical under both core configs
- source-tree migration stories preserve existing V1.1/V1.3 behavior while
  separating runtime, contracts, codecs, scenarios, fixtures, and test support

## Non-Goals

- no new tile capabilities or policy rules
- no changes to capability envelopes, audit records, or replay capsule shape
- no changes to the investment demo product path
- no financial policy, approval, adapter authority, audit schema, or replay
  semantic changes as part of the source-tree migration

### V1.14.S6: Normalize Tickoni source ownership roots

**Status:** Ready for review
**Epic:** #TBD
**Parent roadmap item:** V1.14: Firedancer Process And Shared-Memory Topology
**Labels:** `story`, `platform`

Make source-tree ownership obvious by separating C ABI bindings, codec
implementations, protobuf contracts, canonical Zig contracts, deterministic
demo orchestration, and test fixtures without changing financial behavior.

## Product Outcome

Developers can inspect `src/tickoni` and immediately tell whether a file owns
runtime substrate, canonical contracts, codec boundaries, deterministic demo
orchestration, or test-only data. This reduces accidental ownership drift before
process isolation and shared-memory topology work expands the tree.

## User Story

As a Tickoni developer/operator, I want source paths to encode ownership, so
that future tile, schema, codec, demo, and fixture work can be reviewed without
guessing which layer owns financial correctness.

## Scope

- In scope: move Zig codec bindings from `src/tickoni/c_abi` to
  `src/tickoni/codec`; move protobuf files under `src/tickoni/schema/proto`;
  move V1 money-decision Zig contracts under `src/tickoni/schema/consumer_money`;
  replace ambiguous `src/tickoni/scenarios` with `src/tickoni/demo`.
- In scope: update `build.zig`, imports, proto contract tests, docs, and test
  paths so the repository remains buildable.
- Out of scope: changing tile IDs, link semantics, policy outcomes, audit
  schema, replay capsule shape, model/tool/adapter authority, or financial
  product semantics.

## Preconditions And Assumptions

- Existing V1.1 and V1.3 investment, replay, audit, model, adapter, and
  decision-card behavior is the compatibility baseline.
- `src/tickoni/c_abi` remains only for narrow Zig declarations and wrappers
  around retained Firedancer substrate such as queues and sandboxing.
- The current consumer-money schema namespace is a path cleanup only; domain
  strings such as `investment.intent` and `trading_order.propose` are not
  renamed.

## Acceptance Criteria

- [ ] Given the source tree, when a developer looks for codec bindings and C
      codec implementations, then they are under `src/tickoni/codec`.
- [ ] Given the source tree, when a developer looks for protobuf contracts,
      then they are under `src/tickoni/schema/proto/<domain>/`.
- [ ] Given the source tree, when a developer looks for current V1
      money-decision Zig contracts, then they are under
      `src/tickoni/schema/consumer_money/`.
- [ ] Given the source tree, when a developer looks for deterministic demo
      orchestration, then it is under `src/tickoni/demo/<demo>/`, not
      `src/tickoni/scenarios`.
- [ ] Given existing V1 tests, when the moved modules compile and run, then
      behavior remains unchanged.

### V1.14.S7: Standardize test asset naming and tile module pattern

**Status:** Ready for review
**Epic:** #TBD
**Parent roadmap item:** V1.14: Firedancer Process And Shared-Memory Topology
**Labels:** `story`, `platform`

Make test assets and tile internals predictable by requiring `fixture_`,
`test_`, and `mock_` filename prefixes and documenting the Tickoni tile module
pattern derived from Firedancer's explicit tile-boundary style.

## Product Outcome

Developers can add a new fixture, mock, test, or tile without reverse
engineering existing naming drift. The tree communicates whether a file is
test-only data, a mock server/double, a test root, or tile-owned production
logic.

## User Story

As a Tickoni developer, I want file prefixes and tile module names to be
consistent, so that adding a new tile or test path is mechanical and
reviewable.

## Scope

- In scope: rename test roots to `test_*`, pure mocks and mock servers to
  `mock_*`, fixture builders and data to `fixture_*`, and tile-local audit
  fixtures to `fixture_*`.
- In scope: document the Tickoni tile pattern:
  `mod.zig`, `types.zig`, `messages.zig`, `backend.zig`, `validator.zig`,
  `run.zig`, `codec.zig`, and optional `fixture_*.zig`.
- In scope: update imports, build roots, docs, and fixture references.
- Out of scope: splitting every placeholder tile immediately; small tiles may
  keep only `mod.zig` until they own messages, backend variants, validation,
  or orchestration.

## Preconditions And Assumptions

- Firedancer tile structure is the reference style: explicit tile ownership,
  optional public/private helpers, generated artifacts, fixtures, and
  `test_*` roots, not MVC/MVVM layering.
- Tickoni's Zig tile pattern should preserve `mod.zig` as the public surface
  and move responsibilities into named sibling files only when those
  responsibilities exist.
