# V2.22.S4: Windows retail runtime implementation

**Status:** Backlog
**Epic:** #[github-epic-issue]
**Parent roadmap item:** V2.22: Windows Retail Runtime Support
**Labels:** `story`, `platform`, `enhancement`

Select the first Windows support path and define the Windows-specific build,
install, and runtime scope so consumer Windows users can run deterministic
paper demos without needing Linux.

## Product Outcome

A Windows user can build or install Tickoni, run preflight, execute a
deterministic paper demo, and see platform-tier evidence on a normal Windows
laptop or desktop.

## User Story

As a consumer-money user on Windows, I want to install Tickoni without admin
rights, run a demo, and see my platform tier and isolation limits, so that I
can inspect policy-gated proposals on my own hardware.

## Scope

- In scope: Windows path decision (WSL2, Docker Desktop Linux container,
  Hyper-V VM, or native), Windows-specific Firedancer adaptation plan from
  V2.21.S2, Windows build prerequisites, installer/uninstaller design for
  Windows, Windows preflight checks.
- Out of scope: macOS path (V2.21), Linux implementation (no change), demo
  execution (S6), trust closure (S7).

## Preconditions And Assumptions

- S1 defines tier language (Windows retail runtime tier).
- V2.21.S2 defines the build-scope filter and Firedancer reuse inventory.
- Consumer Windows must not require admin or elevated privileges.
- S3 defines version/doctor/manifest preflight that Windows must implement.
- V2.21.S4 (macOS) establishes the implementation pattern that V2.22 adapts
  for Windows.

## Acceptance Criteria

- [ ] Given a supported Windows version, when the user builds or installs
      Tickoni, then the install is user-scoped by default and does not request
      admin credentials.
- [ ] Given a Windows host, when `tickoni doctor` runs, then it identifies the
      Windows support path (WSL2, Docker, VM, native), reports tier status,
      and lists any missing prerequisites.
- [ ] Given a Windows retail build, when the build system runs, then only the
      Firedancer modules included in V2.21.S2's reuse inventory are compiled.
- [ ] Given the Windows installer, when a user verifies it, then checksums,
      signatures, or attestations are available for manual verification.

### Conditional Acceptance

**Financial capability and policy**

- [ ] N/A - Windows path does not change policy outcomes.

**Audit and replay**

- [ ] N/A - Windows reports tier metadata as defined in S3; conformance is in S6.

- [ ] N/A - Windows does not change tile ownership or link shape; it uses

**Model, tool, adapter, or execution boundary**

**CaseOps API or UI**
