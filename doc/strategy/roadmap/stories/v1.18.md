# V1.18: Replay Proof Bundle And Evidence Integrity

**Status: Planned · Milestone: M4**

**Epic:** #TBD · **Issue:** #TBD

Build the content-addressed evidence store, hash-chained event references in
the replay capsule, agent transcript and tool-call hash references, and expected
outcome verification. V1.11 source-driven replay handles substitution and
fail-closed behavior; this increment adds the cryptographic integrity layer
needed for audit proof bundles and partner-trust evidence.

Extracted from V1.11.S4 (T6–T9).

---

## Product Intent

V1.11 replay reconstructs the investment flow from captured inputs, routes
model calls through `tkmodl` substitution, and fails closed on missing
substitutions. What it does not provide is a tamper-evident bundle: evidence
items are not content-addressed, the replay capsule does not carry hash
references for events, transcript, or tool calls, and there is no expected
outcome field to verify replay results against. V1.18 adds this integrity
layer so that the capsule is self-verifying and the proof bundle can be
shared with auditors and partners without re-running the flow.

## User Story

As an auditor or partner, I can verify a replay proof bundle from content hashes
and capsule references alone, without re-running the investment flow, so that
evidence integrity is self-verifiable and any tamper produces a first-divergence
record at the exact sequence number where the modification occurred.

## What The Operator Sees

- content-addressed evidence items with canonical content hash, stable item id,
  source identity, and sequence number
- replay capsule with ordered event-hash references, transcript hash, tool-call
  hash, and expected outcome field
- first-divergence record on tamper: divergent hash, sequence number, and first
  differing field
- capsule load rejection with reason when event-hash sequence is non-monotonic
  or a hash is missing
- replay outcome mismatch record when the reconstructed outcome differs from
  the expected outcome field

## Success Demo

- [ ] Identical evidence content produces the same hash regardless of capture
  time.
- [ ] Replay capsule with non-monotonic event-hash sequence is rejected at load,
  before any replay step runs.
- [ ] A tampered captured fixture produces a first-divergence record at the
  correct sequence number with the first differing field.
- [ ] A reconstructed outcome that differs from the expected outcome field causes
  replay to fail closed with a divergence record.
- [ ] An unmodified capsule replays cleanly with a matching outcome.

## Release Gate

- `just test-unit-tk` passes with no unexpected skips
- `just test-integration-tk` passes offline against local mocks
- identical evidence content produces the same hash regardless of capture time
- non-monotonic or missing hash is rejected at capsule load
- tamper produces first-divergence record at the correct sequence number
- outcome mismatch fails closed

## Non-Goals

- no changes to replay substitution logic or fail-closed behavior
- no changes to `tkmodl` or `tktool` dispatch
- no new product capabilities or policy rules
- no changes to audit record schema outside the capsule

## WBS

### V1.18.S1: Content-addressed evidence and hash-chained capsule

**Issue:** #TBD

**Description:** Define content-addressed evidence store with canonical content hash, build hash-chained event references into replay capsule, add agent transcript and tool-call hash references, add expected outcome field for verification.

Tasks:

- V1.18.S1.T1: Define a content-addressed evidence store for the investment
  flow: each evidence item has a canonical content hash computed from its type
  and payload, a stable item id, source identity, and sequence number. The same
  content always maps to the same hash regardless of when it was captured.
- V1.18.S1.T2: Build ordered event-hash references into the replay capsule:
  each captured event carries its source event sequence number and event content
  hash. The capsule is invalid if any hash is missing or the sequence is
  non-monotonic.
- V1.18.S1.T3: Add agent role, transcript hash, and tool-call hash references
  to the replay capsule. The transcript hash covers the ordered sequence of
  model requests and responses for the run. The tool-call hash covers the
  ordered sequence of tool requests and adapter results. Each adapter result is
  stored as a content-addressed item with adapter id, invocation sequence
  number, and output hash.
- V1.18.S1.T4: Add expected replay outcome to the capsule: final policy state,
  proposed action when present, and expected policy result. Replay fails closed
  if the reconstructed outcome does not match the expected outcome field.

Acceptance:

- Content-addressed evidence items produce the same hash for identical content
  regardless of capture time.
- Replay capsule event-hash sequence is monotonic; a non-monotonic or missing
  hash is rejected before any replay run begins.
- A reconstructed outcome that differs from the expected outcome field causes
  replay to fail closed with a divergence record.
